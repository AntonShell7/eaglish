ПРАКТИЧЕСКАЯ РАБОТА № 05

Построение простой информационной модели
(система «Школьная библиотека»)


Цель работы: построить простую информационную модель реальной системы,
исследовать её и сделать выводы о поведении системы и об адекватности модели.

Инструмент: электронные таблицы (файл «Модель_школьная_библиотека.xlsx»,
листы «Модель», «Книги», «Читатели», «Выдачи», «Итоги»).


────────────────────────────────────────────────
1. ПОСТАНОВКА ЗАДАЧИ
────────────────────────────────────────────────

Моделируемая система — школьная библиотека: книжный фонд, читатели
и операции выдачи и возврата книг.

Цель построения модели — отслеживать движение фонда, то есть знать
в любой момент, какие экземпляры свободны, у кого книги на руках
и кто задерживает возврат.

Ключевые вопросы, на которые модель должна ответить:
  1. Сколько экземпляров каждой книги сейчас свободно, а сколько на руках?
  2. У кого просрочен возврат и на сколько дней?
  3. Какие разделы фонда самые востребованные?
  4. Какой класс читает активнее других?

Существенные свойства системы (то, что вошло в модель):
  • книга — автор, название, раздел, год издания, число экземпляров;
  • читатель — ФИО, класс;
  • выдача — какая книга, кому, дата выдачи, срок возврата, дата возврата.

Несущественные для этой цели свойства (отброшены): физическое состояние
книги, издательство, цена, номер полки, бумажный формуляр, возраст читателя.


────────────────────────────────────────────────
2. АНАЛИЗ СИСТЕМЫ И ВЫБОР ТИПА МОДЕЛИ
────────────────────────────────────────────────

Выбран тип: знаковая информационная модель, табличная (реляционная).

Обоснование. Все существенные свойства системы — это однотипные записи
с одинаковым набором реквизитов (книги, читатели, выдачи), между которыми
есть связи «один ко многим»: одна книга — много выдач, один читатель —
много выдач. Такие данные естественно ложатся в набор связанных таблиц.
Табличная модель, в отличие от графической (схемы, графы), позволяет
не только хранить данные, но и вычислять по ним ответы формулами,
а при изменении исходных данных — автоматически пересчитывать результат.
Графическое представление (диаграмма) использовано дополнительно —
только для наглядного показа спроса по разделам фонда.


────────────────────────────────────────────────
3. РАЗРАБОТКА СТРУКТУРЫ МОДЕЛИ
────────────────────────────────────────────────

Модель состоит из трёх таблиц данных и одной расчётной.

Таблица «Книги» (12 записей):
    Код книги (ключ) | Автор | Название | Раздел | Год издания | Всего экземпляров

Таблица «Читатели» (10 записей):
    Код читателя (ключ) | ФИО | Класс

Таблица «Выдачи» (25 записей) — связывает две предыдущие:
    № | Код книги | Код читателя | Дата выдачи | Дата возврата
  и вычисляемые поля: Название, Читатель, Класс, Раздел,
    «Вернуть до», Статус, Дней просрочки.

Связи: поле «Код книги» таблицы «Выдачи» ссылается на ключ таблицы «Книги»,
поле «Код читателя» — на ключ таблицы «Читатели». Такая структура исключает
дублирование: название книги хранится один раз, а в записи о выдаче
подставляется автоматически.

Лист «Модель» содержит параметры, которыми можно управлять:
    срок пользования книгой (дней) и расчётная «сегодняшняя» дата.


────────────────────────────────────────────────
4. СБОР И ВВОД ДАННЫХ
────────────────────────────────────────────────

Введены учебные данные: 12 наименований книг (66 экземпляров) четырёх
разделов — «Классика», «Учебники», «Научно-популярная», «Зарубежная проза»;
10 читателей из классов 9В, 10А, 10Б, 11А, 11Б; 25 записей о выдаче
за период с 20 августа по 18 сентября 2026 года.
Данные вымышленные, составлены автором работы; в таблицах они выделены
синим шрифтом, результаты формул — чёрным.


────────────────────────────────────────────────
5. РЕАЛИЗАЦИЯ ЛОГИКИ МОДЕЛИ
────────────────────────────────────────────────

Подстановка данных по ключу (лист «Выдачи»):
    =IFERROR(INDEX(Книги!$C$2:$C$13;MATCH($B2;Книги!$A$2:$A$13;0));"нет такой книги")

Срок возврата — дата выдачи плюс параметр срока:
    =$H2+Модель!$B$19

Статус записи — четыре состояния:
    =IF($J2="";IF(Модель!$B$20>$I2;"Просрочено";"На руках");
        IF($J2>$I2;"Возвращено с опозданием";"Возвращено"))

Число дней просрочки:
    =IF($J2="";MAX(0;Модель!$B$20-$I2);MAX(0;$J2-$I2))

Занятость фонда (лист «Итоги»): сколько экземпляров книги на руках —
    =COUNTIFS(Выдачи!$B$2:$B$26;$A13;Выдачи!$K$2:$K$26;"На руках")
     +COUNTIFS(Выдачи!$B$2:$B$26;$A13;Выдачи!$K$2:$K$26;"Просрочено")
свободно — разность общего числа экземпляров и числа выданных.

Спрос по разделам и активность классов посчитаны функцией COUNTIF
по вычисляемым полям «Раздел» и «Класс» таблицы «Выдачи».

(В файле разделителем аргументов служит запятая — так формулы хранятся
в формате .xlsx; при открытии в русской локали они отображаются с «;».)


────────────────────────────────────────────────
6. ИССЛЕДОВАНИЕ МОДЕЛИ И РЕЗУЛЬТАТЫ
────────────────────────────────────────────────

При параметрах «срок 14 дней», «сегодня 20.09.2026» модель даёт:

    Экземпляров в фонде .............. 66
    Записей о выдаче ................. 25
    Сейчас на руках .................. 20 экз.
        в том числе просрочено ....... 12
    Возвращено вовремя ............... 3
    Возвращено с опозданием .......... 2 (40 % возвратов)

Занятость по книгам: полностью разобрана только «Краткая история времени»
(2 экземпляра из 2 на руках, свободных нет); по остальным наименованиям
свободные экземпляры есть. Самый большой запас — учебники (9 и 10
свободных экземпляров).

Спрос по разделам (выдач всего): Классика — 10, Учебники — 7,
Научно-популярная — 4, Зарубежная проза — 4.

Активность классов: 11А — 9 выдач, 9В — 5, 10А — 4, 11Б — 4, 10Б — 3.

Эксперимент 1. Изменение срока пользования (ячейка «Срок» на листе «Модель»).
При 14 днях просроченными числятся 12 выдач, из них 7 — школьные учебники,
выданные 1–2 сентября на весь учебный год. При изменении срока на 180 дней
просрочки по учебникам исчезают, остаются только 5 задержек по
художественной и научно-популярной литературе.

Эксперимент 2. Сдвиг расчётной даты на неделю вперёд (27.09.2026)
увеличивает число просроченных выдач: в разряд просроченных переходят
книги, выданные 14–18 сентября.


────────────────────────────────────────────────
7. АНАЛИЗ И ИНТЕРПРЕТАЦИЯ РЕЗУЛЬТАТОВ
────────────────────────────────────────────────

Сравнение с реальностью показывает, что модель в целом адекватна:
она правильно воспроизводит движение фонда и даёт ответы на все четыре
поставленных вопроса. Но эксперимент 1 вскрыл упрощение: в модели
один общий срок пользования для всех книг, тогда как в настоящей
библиотеке учебники выдают на учебный год, а художественную литературу —
на две недели. Из-за этого модель завышает число просрочек.
Чтобы устранить это, в таблицу «Книги» нужно добавить реквизит
«Срок пользования» и брать его в формуле «Вернуть до» подстановкой
по коду книги — структура модели такое расширение допускает.

Содержательные выводы по системе:
  • узкое место фонда — научно-популярные книги: «Краткая история времени»
    разобрана полностью, свободных экземпляров нет, её стоит докупить;
  • запас учебников избыточен по сравнению с числом читателей;
  • самый востребованный раздел — классика (40 % всех выдач),
    самый активный класс — 11А;
  • дисциплина возврата низкая: почти половина возвратов с опозданием,
    что говорит о необходимости напоминаний о сроке.

Общий вывод: табличная информационная модель из связанных таблиц
позволяет заменить перебор бумажных формуляров расчётом по формулам,
а её главное свойство — пересчёт при изменении исходных данных —
даёт возможность ставить эксперименты и проверять решения
(изменение срока, прогноз на будущую дату) до их применения
в реальной системе.


────────────────────────────────────────────────
ОТВЕТЫ НА ВОПРОСЫ
────────────────────────────────────────────────

1. Какую реальную систему можно смоделировать?

Практически любую систему, состоящую из объектов с общими свойствами
и связей между ними: школьную библиотеку (выбрана в этой работе),
расписание уроков, успеваемость класса, склад магазина, движение
общественного транспорта, домашний бюджет, базу учеников школы.
Важно, чтобы у моделирования была цель — вопрос, ради ответа
на который модель строится.

2. Какие свойства этой системы будут важны для модели?

Только те, которые влияют на ответ на поставленный вопрос.
Для библиотеки это книга (автор, название, раздел, число экземпляров),
читатель (ФИО, класс) и факт выдачи (что, кому, когда, на какой срок,
когда возвращено). Состояние переплёта, цена или номер полки
для цели «следить за движением фонда» несущественны и в модель
не включаются: лишние свойства усложняют модель, не повышая её точности.

3. Какие инструменты можно использовать для построения модели?

  • электронные таблицы (Microsoft Excel, LibreOffice Calc,
    «Р7-Офис», Google Таблицы) — для табличных моделей с расчётами;
  • системы управления базами данных (LibreOffice Base, Access,
    PostgreSQL, SQLite) — когда данных много и нужны связи и запросы;
  • языки программирования (Python) — для моделей со сложной логикой;
  • редакторы схем и графов (yEd, draw.io) — для графических моделей;
  • специализированные среды моделирования (GeoGebra, Simulink,
    «Живая физика») — для моделей физических процессов.

В этой работе выбраны электронные таблицы: их возможностей достаточно
для связанных таблиц и расчётов, а модель остаётся наглядной.
